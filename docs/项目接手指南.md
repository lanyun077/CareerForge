# CareerForge 项目接手指南

> 更新时间：2026-09-21  
> 当前开发分支：`develop`  
> 远程仓库：`origin`（GitHub `lanyun077/CareerForge`）  
> 项目类型：Next.js 14 + TypeScript 的 AI 求职训练平台

## 1. 项目定位

CareerForge 面向计算机专业学生，提供以下训练闭环：

```text
输入简历 → 推荐 3-5 个职业方向 → 搜索岗位或导入企业 JD
→ 岗位匹配分析 → 岗位专属模拟面试 → 回答评分与复盘
→ 二次专项挑战 → 两轮表现对比
```

系统是求职训练辅助工具，不预测真实录取概率，不替代真实面试官，也不基于性别、年龄、地域或学校层次评价用户。

## 2. 快速启动

要求：Node.js `>=18.17`。

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

打开 <http://localhost:3000>。不配置大模型时，系统仍可使用固定题库、规则追问和规则评分跑通完整流程。

## 3. 环境变量

`.env.local` 只保存在本地，禁止提交。API Key 不要写入 README、测试脚本、日志或前端代码。

```env
OPENAI_API_KEY=
OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
OPENAI_MODEL=qwen-plus

# 扫描 PDF OCR，需要支持图片输入的视觉模型
OCR_MODEL=qwen-vl-plus
OCR_API_KEY=
OCR_BASE_URL=

# PostgreSQL / Supabase；未配置时使用内存存储
DATABASE_URL=

# 语音转写，可选
ASR_API_KEY=
ASR_BASE_URL=
ASR_MODEL=whisper-1
```

OCR 会优先使用 `OCR_API_KEY` / `OCR_BASE_URL`，为空时复用普通模型配置。OCR 模型必须支持 `image_url` 或图片输入，否则接口会降级为粘贴文本。

## 4. PostgreSQL 初始化

配置 `DATABASE_URL` 后，在数据库中执行：

```bash
psql "$DATABASE_URL" -f db/schema.sql
```

持久化表包括：

- `resume_analyses`：简历分析和岗位快照
- `interview_sessions`：面试状态、问题、回答和岗位快照
- `review_reports`：复盘报告
- `job_postings`：用户导入的企业 JD
- `recommendation_runs`：一次简历推荐的完整结果
- `role_snapshots`：推荐、简历分析、面试会话使用时的岗位快照

数据库异常时，`StoreFacade` 会降级到内存存储。运行 `GET /api/health` 可查看当前实际模式。

## 6. 核心数据模型

- `RoleProfile`：稳定的职业方向，例如 Python 后端、前端、数据分析、Agent、LLM、算法、云原生和安全。
- `JobPosting`：具体企业岗位或用户导入的 JD，包含原始描述、来源和岗位快照。
- `RoleTarget`：业务服务接受的统一目标类型：`RoleProfile | JobPosting`。
- 岗位快照：简历分析、推荐结果和面试会话会保存当时的岗位内容，避免岗位配置更新后历史报告失真。

## 7. 主要接口

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/health` | 查看模型、存储和 ASR 状态 |
| `GET` | `/api/roles` | 获取静态职业方向和已保存岗位 |
| `POST` | `/api/roles/recommend` | 根据简历推荐最多 5 个方向 |
| `POST` | `/api/roles/import` | 将 JD 解析为 `JobPosting` |
| `POST` | `/api/resume/parse-pdf` | 提取文本 PDF；无文本层时尝试 OCR |
| `POST` | `/api/resume/analyze` | 分析简历与目标岗位匹配情况 |
| `POST` | `/api/interview/start` | 开始首轮或二次专项面试 |
| `POST` | `/api/interview/answer` | 提交回答并推进状态机 |
| `GET` | `/api/report/:sessionId` | 生成或读取复盘报告 |
| `GET` | `/api/records` | 获取训练记录 |
| `DELETE` | `/api/records?id=...` | 级联删除训练数据 |

## 8. 模型职责边界

大模型负责简历/JD 语义理解、推荐语义匹配、个性化出题与追问、回答证据分析、复盘文案和扫描 PDF 文字识别。

程序负责规则匹配、推荐排序、星级换算、面试状态机、题数和追问上限、字段校验、固定权重总分、持久化和失败降级。不要把面试推进、总分计算或权限边界交给模型自由决定。

## 10. 当前已知限制

- OCR 已接入视觉模型链路，但还需要用真实扫描简历样本做识别质量回归。
- OCR 最多处理 8 页，每页选择最大图片；复杂多栏、旋转页面和低清图片可能需要继续优化。
- Word/DOCX 简历解析尚未接入。
- 未配置 `DATABASE_URL` 时，重启服务会丢失训练记录和用户导入岗位。
- 当前推荐的是稳定职业方向，不是招聘平台实时企业职位。
- 未接入用户认证，不适合直接暴露到多用户生产环境。
- 训练记录删除接口目前按 session id 操作，正式多用户版本必须增加用户身份校验。
- 职位数据尚未接入授权的招聘 API 或企业招聘 Feed。

## 11. 推荐下一步

1. 用真实扫描 PDF 验证 OCR，记录准确率、耗时和成本。
2. 增加 OCR 结果预览和人工修正，再进入岗位推荐。
3. 接入 Word/DOCX 简历解析。
4. 为 `RoleProfile`、`JobPosting` 和 `MatchResult` 增加版本及历史查询。
5. 增加登录、用户数据隔离、简历版本和岗位收藏。
6. 接入合法职位数据源，处理来源、更新时间、过期和去重。
7. 建立 CI，自动执行构建、冒烟和数据库迁移检查。
8. 增加模型调用耗时、失败率、降级率和成本监控。

提交前确认：`git status`、`git diff --check`、`npm run build` 和 `npm run smoke -- http://localhost:3210`。

禁止提交 `.env.local`、API Key、数据库密码、`.next/`、`node_modules/`、`.idea/`、生成的测试 PDF 和本地日志。
