## 一、状态说明

| 状态 | 含义 |
|---|---|
| 已完成 | 已实现并通过当前阶段验证 |
| 进行中 | 已有实现，但仍有体验、数据或稳定性工作未完成 |
| 待开始 | 尚未进入开发 |
| 阻塞 | 依赖外部资源、授权或关键决策 |

优先级说明：`P0` 为当前必须完成，`P1` 为下一阶段核心任务，`P2` 为增强能力，`P3` 为长期规划。

## 五、推荐迭代顺序

### 迭代 1：完成 MVP 体验收尾

目标任务：`UX-01`、`UX-02`、`UX-03`、`UX-04`。

验收重点：

- 推荐结果能清楚解释“为什么推荐”和“还缺什么”。
- 用户始终知道当前位于简历、匹配、面试还是报告阶段。
- 加载、空数据、模型降级和错误状态都有明确反馈。
- 桌面端与常见移动端宽度下无文字溢出或控件重叠。

### 迭代 2：重构数据模型

目标任务：`DATA-01`、`DATA-02`、`DATA-03`、`DATA-04`。

验收重点：

- 职业方向与企业具体职位明确分离。
- 每次推荐保存岗位快照，避免岗位更新后历史报告失真。
- 自定义 JD、推荐结果和训练记录重启后可恢复。
- 现有 MVP 接口和页面完成回归测试。

### 迭代 3：接入真实职位试点

目标任务：`JOB-01`、`JOB-02`、`JOB-03`、`JOB-04`。

验收重点：

- 数据来源合法、可持续，并遵守服务条款。
- 每条职位展示来源、原始链接、发布时间和更新时间。
- 可按关键词、城市、经验、薪资和远程筛选。
- 过期、重复和信息不完整的职位不会污染推荐结果。

### 迭代 4：完善文档解析与用户能力

目标任务：`DOC-01`、`DOC-02`、`USER-01`、`USER-02`、`USER-03`。

验收重点：

- 文本 PDF、扫描 PDF 和 Word 简历都有明确处理路径。
- 用户可管理多个简历版本、收藏职位和投递状态。
- 数据访问、删除和隐私边界可验证。

### 迭代 5：生产化

目标任务：`OPS-01`、`OPS-02`、`OPS-03`。

验收重点：

- 提交代码后自动构建和测试。
- 模型调用失败率、降级率、耗时和成本可观察。
- 线上完成安全检查、性能测试和核心流程验收。

## 六、阶段推进规则

每个阶段按以下规则推进：

1. 开始任务前确认任务编号、依赖和验收标准。
2. 开发过程中只将实际已实现的任务标记为“进行中”。
3. 完成功能后至少执行构建、相关接口测试和关键页面检查。
4. 满足表格中的完成标准后才能标记为“已完成”。
5. 阶段内所有 `P0` 任务完成后，才进入下一阶段。
6. 外部 API、数据授权或产品决策未确定时标记为“阻塞”，不以临时爬虫替代。
7. 每次合并或发布后更新本文档的日期、任务状态和阶段状态。

## 七、当前建议

下一次开发应从 **迭代 1：完成 MVP 体验收尾** 开始，执行顺序建议为：

```text
推荐卡片信息增强
→ 面试页 UI
→ 报告页 UI
→ 记录页 UI
→ 完整流程回归
→ 进入数据模型拆分
```

本阶段暂不优先接入未经授权的招聘网站，也不先开发账户系统。先把已有闭环做得清晰、稳定、可演示，再扩展真实职位与长期数据能力。
