# 部署指南

> 目标：把 CareerForge 部署为**可公网访问的 Web 演示环境**（方案 5.2 / 待确认事项 #2）。
> 推荐 Vercel（Next.js 原生支持，免费额度足够比赛演示）；数据库用 Supabase 免费版。

## 方案一（推荐）：Vercel + Supabase

### 1. 创建 Supabase 项目并建表

1. 注册 [supabase.com](https://supabase.com) → 新建项目（区域选近的，如东京/新加坡）
2. 打开 SQL Editor，把 [db/schema.sql](../db/schema.sql) 全文粘贴执行
3. 在 `Project Settings → Database → Connection string → URI` 复制连接串
   （形如 `postgresql://postgres.[ref]:[password]@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres`）

> 注意：Supabase 的 Transaction pooler（6543 端口）适合 Serverless；
> 如果用 Direct connection（5432），请确认 Vercel 出口 IP 是否被允许。
> URL 中的特殊字符（如密码含 `@`）需做 URL 编码。

### 2. 部署到 Vercel

```bash
npm i -g vercel
vercel login
vercel          # 首次：关联 lanyun077/CareerForge 仓库，一路默认即可
```

或网页方式：[vercel.com/new](https://vercel.com/new) → Import GitHub 仓库 `lanyun077/CareerForge` → Deploy（零配置，自动识别 Next.js）。

### 3. 配置环境变量

Vercel 项目 → Settings → Environment Variables，添加（Production + Preview 都勾）：

| 变量 | 值 | 说明 |
|---|---|---|
| `OPENAI_API_KEY` | 你的模型 Key | **必配**，否则公网演示走兜底模式 |
| `OPENAI_BASE_URL` | 如 `https://open.bigmodel.cn/api/paas/v4` | OpenAI-compatible 均可 |
| `OPENAI_MODEL` | 如 `glm-4-flash` | 建议选便宜快速的模型 |
| `DATABASE_URL` | Supabase 连接串 | 配置后训练记录持久化；不配则为内存存储 |
| `ASR_API_KEY` 等 | 可选 | 语音转写，不配则纯文字面试 |

改完环境变量需要 **Redeploy** 一次才生效。

### 4. 验证清单

- [ ] 打开 `https://<project>.vercel.app`，首页徽章显示「在线模式 · 大模型已配置」
- [ ] 存储徽章显示「PostgreSQL（持久化）」
- [ ] 用「演示简历」走完一轮训练，重启部署后训练记录仍在（`/records` 页可见）
- [ ] 使用隔离试用账户完成人工闭环验收；自动冒烟只对专用本地测试实例运行。

### 常见问题

- **首页显示兜底模式**：环境变量没配对或没 Redeploy；检查 `OPENAI_API_KEY` 拼写。
- **存储显示内存**：`DATABASE_URL` 连不通（密码错 / 端口错 / IP 限制）。后端日志有
  `[store] PostgreSQL 不可用` 告警；服务仍可用（自动降级），修好后重启即可恢复。
- **冷启动慢**：Serverless 函数首次请求约 2-5 秒，正常现象；演示前先预热一次。

## 方案二：自有服务器 / 内网演示

```bash
git clone https://github.com/lanyun077/CareerForge.git
cd CareerForge
npm ci
npm run build
DATABASE_URL=postgresql://... OPENAI_API_KEY=... npm run start -- -p 3000
```

配 systemd / pm2 守护即可。无外网环境可不配模型 Key，直接走题库兜底模式演示（完整闭环可用）。

## 演示环境建议

- 比赛前一天**完整彩排一次**：演示简历 → 面试 → 报告 → 二轮 → 对比
- 准备好兜底：万一模型服务现场故障，界面会自动降级（题库+规则），流程不中断，
  汇报时可以坦然说明这是设计好的降级能力（方案 六，反而是加分项）


## 面试设置与语音输入（2026-09-22）

升级前执行 db/schema.sql，其中新增 interview_sessions.settings JSONB 列，用于保存题数、难度与追问上限；二轮沿用首轮配置。

语音输入需配置 ASR_API_KEY、ASR_BASE_URL、ASR_MODEL，服务必须支持 multipart POST /audio/transcriptions 并返回字符串 text。默认地址 https://api.openai.com/v1，默认模型 whisper-1；密钥只放服务端环境变量。修改配置后重启服务。浏览器需HTTPS或localhost及麦克风权限。每次录音最长120秒、10 MiB，停止后发送到服务商，本应用不保存音频；服务商保留策略需按实际服务核实。用户核对并追加转写后再提交回答。

本地无配置时显示文字输入提示。上线前需人工验证麦克风允许/拒绝、静音、设备中断、停止转写、切题释放设备及中文识别质量；目前不具备实时转写和语音质量检测。


## 受控岗位采集（2026-09-23）

采集入口支持 https://job-boards.greenhouse.io/{board}/jobs/{id} 与旧 boards.greenhouse.io 页面格式，仅调用固定 Greenhouse 官方公开API。无需第三方密钥；服务器须允许该API的HTTPS出站及公网IPv4 DNS。不开启任意URL代理，不跟随跳转。已用GitLab公开岗位实测，其他招聘平台继续手动粘贴并记录来源。

来源数据保存在现有岗位/快照/报告JSON字段，无新增数据库迁移（此前面试settings迁移仍需执行）。采集证明30分钟有效，进程重启失效；多实例暂不支持跨实例验证签名和共享配额，应采用单实例受控试用。采集每用户6次/分钟、每进程30次/分钟、并发3、超时10秒、响应512 KiB；认证启用时沿用现有登录与数据隔离。local-demo不提供身份隔离，不可直接公开多人使用。

采集是有限规则提取与脱敏，不保证去除所有个人信息；确认前核对正文。只保存训练所需岗位信息，正式运营前完成来源使用条款、保留期限、撤回清理流程及跨公司独立质量验收。来源200响应不代表仍招聘。
