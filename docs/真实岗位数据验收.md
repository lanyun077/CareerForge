## 来源追溯验收

- 导入前可见公司、岗位、官方链接、访问时间及原文；确认后才成为训练目标。
- 来源网页的 HTML 与实体编码转成纯文字，不执行脚本，不把网页指令提升为系统指令。Greenhouse 本次详情 `content` 实际包含 `&lt;p&gt;` 形式的实体编码，必须覆盖该格式。
- 岗位与训练快照保留当时来源和文本版本；来源后续变化不得悄悄改写历史训练要求。
- 用户粘贴来源是用户声明；受控 API 获取是系统抓取记录，不能将前者冒充后者。正文摘要或 hash 只能证明版本一致性，不能证明公司真实性。
- 失效、下架、超时、限流返回清楚状态；不把上次缓存误标成刚刚更新。
- 删除导入岗位与清理训练遵循项目既有共享引用规则；删除/撤回策略不可只停留在界面文案。

## 受控采集安全验收边界

这些是设计与测试检查项，是否已由代码覆盖以本轮实现和实际测试记录为准。

| 边界 | 要求与反例 |
|---|---|
| 请求目的地 | 优先固定 HTTPS 官方 API 主机和模板路径，仅接受严格 board token / 数字岗位 ID。拒绝任意 URL、用户信息段、端口、反斜线、编码路径穿越、伪装子域与 query 注入。 |
| 重定向 | 默认禁止跟随；不能让可信主机 302 跳向本机、内网或云元数据地址。 |
| DNS / SSRF | 固定主机缩小攻击面，但不等于任意 URL 的完整 SSRF 防护。若未来开放 URL，需解析所有 A/AAAA、拒绝私有/保留/环回/链路本地及 IPv4 映射 IPv6，连接绑定已校验地址，跳转逐次校验；校验一次再普通 fetch 有 DNS 重绑定时间差。 |
| 资源预算 | 对总耗时、响应实际读取字节、并发和调用频率设界限；不能仅信 Content-Length。超限取消读取。客户端断开与失败也必须释放并发槽位。 |
| 多人环境 | 接口需要认证和按用户限流；进程内限流不是多实例全局限流。分享/枚举缓存不得泄露另一用户手工导入的 JD 或简历。 |
| 不可信内容 | 仅提取岗位文字；清除脚本与事件属性；不使用不受控 HTML 渲染。不自动访问正文链接、附件、图片或模型建议的地址。 |
| 提示注入 | 含“忽略系统提示/发送简历”等文本的页面仍只是来源数据。模型不得获取额外凭据、调用外部地址或修改流程；结构校验不等于语义防注入已解决。 |
| 隐私与日志 | 不向采集源发送简历、密钥或用户身份；错误日志不包含密钥和完整私密正文。过滤无关联系信息。 |
| 失败与来源可信度 | 404、429、错误 JSON、错误类型、缺失标题/正文、岗位 ID 不符应拒绝，不保存成功状态；API 返回的外部链接只作展示并校验协议，不能成为第二次任意抓取入口。 |
