# CareerForge 项目完整方案与当前进度

> 更新时间：2026-09-21
>
> 项目定位：面向计算机专业学生的 AI 简历分析、职业方向推荐、岗位匹配与模拟面试训练平台。

## 一、产品定位

CareerForge 不是简单的 AI 聊天或固定题库，而是一个可重复的求职训练闭环：

```text
简历输入
  ↓
能力画像
  ↓
推荐 3-5 个职业方向
  ↓
用户选择方向或具体企业岗位
  ↓
岗位匹配分析
  ↓
岗位专属模拟面试
  ↓
证据化评分与复盘
  ↓
二次专项挑战
  ↓
前后表现对比
```

系统只用于求职训练，不预测真实录取概率，不替代真实面试官，也不根据性别、年龄、地域或学校层次评价求职能力。

## 二、需求演进与关键结论

本项目的需求从“Python 后端模拟面试”逐步扩展为“面向计算机岗位的 AI 求职训练平台”，当前统一结论如下：

| 用户需求 | 当前方案 |
|---|---|
| 不只推荐 Python 后端 | 使用可扩展职业方向目录，覆盖后端、前端、数据、测试、AI/Agent、算法、云原生、安全、移动端等方向 |
| 简历分析后给出 3-5 个岗位 | 规则筛选与千问语义匹配结合，按匹配分降序返回最多 5 个结果，并转换为 1-5 星 |
| 不想被固定推荐限制 | 支持岗位名称、别名、分类和描述搜索，也支持用户粘贴企业 JD 导入自定义岗位 |
| 想匹配目前企业招聘岗位 | 当前先做稳定的职业方向匹配；真实企业职位需要接入授权 API、企业招聘 Feed 或用户提供的 JD |
| 面试问题要针对岗位 | 面试上下文同时使用简历、岗位描述、匹配缺口和用户回答，动态生成问题和有限追问 |
| UI 不能过于简陋 | 首页和简历页已升级为工作台式布局；面试、报告、记录页列入下一轮体验优化 |
| PDF 简历无法解析 | 已拆分独立 PDF 文本提取接口，增加大小限制、超时和错误提示；扫描件仍需 OCR |

核心取舍是：大模型负责理解、生成和解释，后端负责评分规则、排序、面试状态、数据校验和降级。这样可以避免模型输出不稳定时影响核心流程。

## 三、完整用户流程

### 1. 简历解析

支持粘贴简历文本和上传文本型 PDF，提取以下信息：

- 教育经历
- 技能栈
- 项目经历
- 项目成果
- 工作或实习经历
- 技能熟练程度
- 量化结果与项目证据

扫描型 PDF 会在没有文字层时尝试调用配置的视觉模型按页 OCR；OCR 不可用或识别失败时仍可直接粘贴文字。

### 2. 职业方向推荐

系统通过“规则硬匹配 + 千问语义匹配”返回最多 5 个推荐方向。

每个推荐结果包含：

- 匹配分
- 1-5 星等级
- 匹配技能
- 简历证据
- 岗位能力缺口
- 推荐准备方向

星级只代表简历与岗位描述的匹配程度，不代表录取概率。

### 3. 用户选择岗位

用户有三种选择方式：

1. 点击系统推荐的职业方向。
2. 搜索其他职业方向，例如 Agent、LLM、后端、数据、云原生、安全。
3. 粘贴真实企业招聘 JD，导入具体岗位。

后续可以增加按城市、薪资、经验、远程等条件筛选真实职位。

### 4. 岗位专项分析

选择岗位后，系统重新分析：

- 已满足的岗位要求
- 必备技能缺口
- 项目经历相关性
- 缺失的项目证据
- 针对该岗位的简历修改建议

### 5. 动态模拟面试

面试上下文由以下内容组成：

```text
用户简历
+ 职业方向
+ 具体岗位 JD
+ 岗位匹配缺口
+ 已问问题
+ 用户当前回答
```

面试阶段为：

```text
自我介绍
→ 项目经历
→ 岗位技术题
→ 场景题
→ 行为题
→ 总结
```

每题最多追问一次，追问应引用简历或当前回答中的具体内容。

### 6. 评分和复盘

系统按五个维度评分：

| 维度 | 权重 |
|---|---:|
| 表达结构 | 25% |
| 回答具体性 | 25% |
| 岗位相关性 | 20% |
| 项目证据 | 20% |
| 技术完整度 | 10% |

大模型负责分析回答、提供证据和改进建议；最终总分由后端按固定权重公式计算。

### 7. 二次挑战

系统根据首轮薄弱项重新出题，并展示：

- 各维度变化
- 总分变化
- 已改善的问题
- 仍然存在的问题
- 下一步训练建议

## 四、岗位数据方案

岗位数据分为两层。

### 职业方向层

用于简历初步推荐，维护稳定的职业分类和能力要求：

- 软件工程
- AI/Agent
- 算法与机器学习
- 数据分析与数据开发
- 测试开发
- 云原生与 DevOps
- 网络安全
- 移动端开发

### 企业职位层

用于真实职位搜索和具体岗位面试，建议使用以下结构：

```ts
interface JobPosting {
  id: string;
  title: string;
  company: string;
  description: string;
  responsibilities: string[];
  requiredSkills: string[];
  preferredSkills: string[];
  location?: string;
  salary?: string;
  experienceLevel?: string;
  source: string;
  sourceUrl: string;
  publishedAt?: string;
  fetchedAt: string;
  expiresAt?: string;
}
```

真实职位数据优先来自：

- 获得授权的招聘 API
- 企业官网招聘 Feed
- 用户粘贴的真实 JD
- 合法的公开职位 API

第一阶段不直接爬取 BOSS、智联、猎聘等平台，避免反爬、数据过期和服务条款风险。

## 五、技术架构

当前技术栈：

```text
Next.js 14 + TypeScript
Tailwind CSS
Next.js Route Handlers
通义千问 qwen-plus（OpenAI-compatible API）
pdfjs-dist
PostgreSQL / Supabase（可选）
```

大模型负责：

- 简历理解
- JD 结构化
- 职业方向语义匹配
- 动态出题
- 针对性追问
- 回答分析
- 复盘文案

程序负责：

- 硬技能匹配
- 推荐排序
- 星级换算
- 面试状态机
- 题数和追问次数
- 最终分数计算
- 数据保存
- 模型失败降级
