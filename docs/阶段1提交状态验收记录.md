# 阶段 1：回答提交与状态一致性

日期：2026-09-22；分支 `codex/baseline-validation`；基于 `985e13a`，本次变更尚未提交。

## 行为与接口

修复前运行 `node scripts/smoke-answer-state.mjs`，同一主回答重试被当成追问回答并推进到下一题，断言失败。修复后：

- `POST /api/interview/answer` 必须提供 `{ sessionId, questionId, answer }`。回答主问题时传主问题 ID，回答追问时传追问 ID；缺少标识返回 422，旧客户端需要刷新或升级。
- 同一问题与相同回答（trim 后最多 5000 字）重试，返回当前会话和对应事件，不重复推进；不同的已回答内容、未知或过期问题返回 409。
- 内存会话读写使用副本，避免保存前修改共享对象。新增异步 `Store.updateSession`，仅在会话 active 且 questions 与读取时一致时保存，不存在的会话不会被重新创建。
- PostgreSQL 使用单条 UPDATE 的 JSONB 原状态条件，无 schema 变更。该更新发生数据库异常时返回 503，不切内存重写；其他旧 Store 操作的降级策略仍未整体修复。
- 页面用即时锁阻止连续点击，请求期间禁用输入；失败保留输入，409 后禁用提交并提供加载最新问题入口。加载后保留旧文本并提示核对。进度、阶段和结构指示按后端 currentPlanIndex 展示，追问未完成时不提前推进。
